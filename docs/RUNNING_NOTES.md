# 实测跑通记录（供社区参考）

> 环境：**NVIDIA T4 16GB** · 宿主内存 30GB(根 cgroup 34GB) · MinimaxH3-ONNX 40GB bf16 逐块流式
> 关键：用 **24GB cgroup 内存上限** 圈住后端（`run-h3-backend-24gb.sh`），解决宿主 OOM。

## ✅ 实测 1：0.2MP × 5 秒（文生视频，turbo 4 步）

| 项 | 值 |
|---|---|
| 分辨率 | **608 × 352（≈0.2 MP）** |
| 时长 | **5 秒** |
| 步数 | turbo 4（Ref2VA Turbo LoRA）|
| 提示词 | 文生视频 |
| 输出 | h264 视频 + aac 音频(32000Hz)，5.000s，~353KB |

### 用时（真实计时）
- 提交：`2026-09-07 13:30:42 UTC`
- 完成：`2026-09-07 15:20:20 UTC`
- **总耗时：≈ 110 分钟（约 1 小时 50 分）**

### 内存表现（每若干秒采样）
- 进程 anon 峰值：**仅 ~5.4–7.1 GB**
- 24GB cgroup 内：**全程零 OOM、零崩溃**
- 说明：内存根本不是瓶颈（anon 极低）；瓶颈是 **CPU 逐块搬运权重 + 块间串行**（GPU util ~0–29%，显存只用 ~37%）

### 结论
- **24GB 限制方案有效**：0.2MP×5s 大任务可稳定跑通、完整出片，不撞宿主 OOM。
- **速度参考**：T4 + 40GB bf16 逐块流式下，0.2MP×5s ≈ 110 分钟。**分辨率/时长每增大，耗时近似像素×帧数线性增长**，请据此规划：
  - 128×128 / ~1s ≈ 4 分钟（之前 128px 实测）
  - 256×256 / ~2s ≈ 15–20 分钟（实测中段）
  - 608×352 / 5s ≈ 110 分钟（本次实测）

## 想让 GPU 吃满、提速（供社区参考）
- 40GB bf16 放不进 16GB 显存 → 只能流式 → CPU 搬运成瓶颈、GPU 空转。
- **换更小模型源**（GGUF Q3_K ~15.5GB 几乎能整进 16GB 显存）能显著提高 GPU 利用率与速度；或换更大显存卡。

## 复现
```bash
# 1) 用 24GB 内存上限启动后端
cd <MinimaxH3-ONNX>
bash run-h3-backend-24gb.sh 24
# 2) 起前端
.venv/bin/python gradio_frontend_amd/app_video_tab.py \
    --backend http://127.0.0.1:7860 --host 127.0.0.1 --port 7862
# 3) 网页里生成即可实时看 block 进度；内存上限可手动改(0=不限)
```
